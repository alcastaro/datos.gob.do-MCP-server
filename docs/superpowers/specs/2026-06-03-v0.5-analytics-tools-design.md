## New tools

### 1. `quantiles_resource`

**Purpose:** Return percentile distribution of numeric columns in a cached resource.

**Parameters:**
- `url: str` — resource URL (same as all analytics tools)
- `format: str` — CKAN format string
- `columns: list[str] | None` — columns to analyze; `None` = all numeric columns
- `percentiles: list[float]` — default `[0.25, 0.5, 0.75, 0.90, 0.95, 0.99]`; values must be in (0, 1)
- `filters: list[dict] | None` — same syntax as `filter_resource`; applied before computing

**Implementation:**
```sql
SELECT
  QUANTILE_CONT("col", [0.25, 0.5, 0.75, 0.90, 0.95, 0.99]) AS quantiles,
  MIN("col") AS min, MAX("col") AS max, AVG("col") AS mean,
  COUNT("col") AS non_null_count, COUNT(*) - COUNT("col") AS null_count
FROM data [WHERE ...]
```

DuckDB returns `QUANTILE_CONT` as an array; unzip into named keys in Python.

**Return shape:**
```json
{
  "source_url": "...",
  "row_count": 826432,
  "columns": [
    {
      "name": "Sueldo Bruto",
      "type": "DOUBLE",
      "non_null_count": 826430,
      "null_count": 2,
      "min": 5000,
      "max": 950000,
      "mean": 48234.5,
      "p25": 28000,
      "p50": 38500,
      "p75": 55000,
      "p90": 82000,
      "p95": 110000,
      "p99": 320000
    }
  ]
}
```

**Annotations:** `readOnlyHint: True, openWorldHint: True`

### 2. `find_duplicates_resource`

**Purpose:** Find rows that are duplicated on a given set of columns (or all columns).

**Parameters:**
- `url: str`
- `format: str`
- `columns: list[str] | None` — columns to check for duplication; `None` = all columns
- `filters: list[dict] | None` — pre-filter before duplicate check
- `limit: int` — max duplicate groups to return (1–500, default 50)

**Implementation:**
```sql
SELECT <columns>, COUNT(*) AS duplicate_count
FROM data [WHERE ...]
GROUP BY <columns>
HAVING COUNT(*) > 1
ORDER BY duplicate_count DESC
LIMIT <limit>
```

**Return shape:**
```json
{
  "source_url": "...",
  "columns_checked": ["Nombre", "Cedula"],
  "duplicate_groups_found": 142,
  "groups_returned": 50,
  "total_duplicate_rows": 318,
  "rows": [
    ["ANA PEREZ", "001-1234567-8", 3],
    ...
  ],
  "columns": ["Nombre", "Cedula", "duplicate_count"]
}
```

**Annotations:** `readOnlyHint: True, openWorldHint: True`

### 3. `detect_outliers_resource`

**Purpose:** Find rows where numeric column values fall outside the IQR fence
(`< Q1 - 1.5*IQR` or `> Q3 + 1.5*IQR`).

**Parameters:**
- `url: str`
- `format: str`
- `column: str` — single numeric column to check (one column per call)
- `filters: list[dict] | None` — pre-filter before outlier check
- `limit: int` — max outlier rows to return (1–500, default 100)

**Implementation (single CTE pass):**
```sql
WITH stats AS (
  SELECT
    QUANTILE_CONT("col", 0.25) AS q1,
    QUANTILE_CONT("col", 0.75) AS q3
  FROM data [WHERE ...]
),
bounds AS (
  SELECT
    q1 - 1.5*(q3 - q1) AS lower_fence,
    q3 + 1.5*(q3 - q1) AS upper_fence,
    q1, q3
  FROM stats
)
SELECT data.*, bounds.lower_fence, bounds.upper_fence
FROM data, bounds
WHERE "col" < bounds.lower_fence OR "col" > bounds.upper_fence
ORDER BY ABS("col" - (bounds.q1 + bounds.q3) / 2) DESC
LIMIT <limit>
```

**Return shape:**
```json
{
  "source_url": "...",
  "column": "Sueldo Bruto",
  "method": "IQR",
  "q1": 28000,
  "q3": 55000,
  "iqr": 27000,
  "lower_fence": -12500,
  "upper_fence": 95500,
  "outlier_count_estimate": 1247,
  "rows_returned": 100,
  "columns": ["Nombre", "Sueldo Bruto", "lower_fence", "upper_fence"],
  "rows": [...]
}
```

Note: negative `lower_fence` is valid (salary can't be negative, but the fence
may be). The model can interpret this.

**Annotations:** `readOnlyHint: True, openWorldHint: True`

### 4. `save_query_to_csv`

**Purpose:** Run a filter/aggregate (or raw SQL) against a cached resource and
write the result to a local CSV file. Export endpoint for analysis workflows.

**Parameters:**
- `url: str`
- `format: str`
- `dest: str | None` — absolute path for output file. Must end `.csv` or `.tsv`.
  No `..` allowed. If `None`, auto-generates to `~/Downloads/datosgobdo-exports/<slug>-<ts>.csv`.
- `sql: str | None` — read-only SQL (same rules as `query_resource`). If given, used.
- `filters: list[dict] | None` — if `sql` is None, filter syntax from `filter_resource`.
- `columns: list[str] | None` — columns to include (ignored if `sql` given).
- `limit: int` — hard cap on rows written (1–100000, default 10000).

**Security:**
- `dest` validated: resolved absolute path, no `..` components, must be under
  a user-writable directory, must not be a system path (`/etc`, `/usr`, `/bin`, etc.).
- If `dest` already exists → return `{"error": "File exists. Pass overwrite=True to replace."}`.
- `overwrite: bool = False` param to allow explicit overwrite.
- SQL uses `_validate_sql` + `_open_sandboxed` same as `query_resource`.

**Return shape:**
```json
{
  "path": "/Users/alcastaro/Downloads/datosgobdo-exports/nomina-2026-06-03T14-23.csv",
  "rows_written": 8342,
  "columns": ["Nombre", "Departamento", "Sueldo Bruto"],
  "bytes_written": 487293
}
```

**Annotations:** `readOnlyHint: False, openWorldHint: True, destructiveHint: False`
(creates new file; doesn't destroy existing data unless `overwrite=True`).

## Deferred Phase 2 items (also in v0.5)

### #5 — Skip HEAD on warm cache

**Problem:** `ensure_cached()` always issues a HEAD request to compute the
ETag/Last-Modified version key — even when the Parquet file is already on disk.
A portal outage breaks ALL cached reads.

**Fix:** When a cache entry exists for a URL (key stored in index), skip the HEAD
and return the cached Parquet immediately. Only HEAD on cache miss or if the
caller explicitly requests a freshness check.

**Implementation:**
- Add URL→key reverse lookup to `_index` in `LocalDiskCache`.
- `ensure_cached()` checks `cache.get_by_url(url)` first; if hit, return without HEAD.
- Add `force_refresh: bool = False` param to `ensure_cached()` for explicit invalidation.

### #6 — Unified error model

**Problem:** `ckan.py` raises `RuntimeError` (FastMCP converts to MCP error — model
gets an error response, not a tool result). `analytics.py` returns `{"error": "..."}` in
the tool result (model sees it as data and can try to recover). Two behaviors, no docs.

**Decision:** Keep the `analytics.py` pattern — return `{"error": ..., "hint": ...}` in
the result. The model can read the hint and try a recovery tool.

**Fix `ckan.py`:**
- Wrap `ckan_request()` exceptions in each public function → return `{"error": ..., "hint": ...}`.
- `hint` should name the recovery tool: e.g. `"Use autocomplete with kind='organization' to find valid slugs."`
- Update `CLAUDE.md` with the documented error model.

## `outputSchema` / `structuredContent` (#10)

Add to the **4 new tools only** in v0.5. Retrofit existing tools in Phase 4.

Pattern (FastMCP):
```python
@mcp.tool(
    annotations=_ro("Quantiles of numeric columns"),
    output_schema=QUANTILES_SCHEMA,  # JSON Schema dict
)
async def quantiles_resource(...) -> dict:
    result = await _quantiles_resource(...)
    # structuredContent is attached by FastMCP when output_schema is set
    return result
```

Each tool gets a tight JSON Schema for its return shape (as specified above).
Always keep the text fallback (`content[].text = json.dumps(result)`) — not all hosts
read `structuredContent` yet.

## Test strategy

- All 4 new tools: hermetic tests with `httpx_mock` + `tmp_cache_dir` (same pattern as existing analytics tests).
- `save_query_to_csv`: test with `tmp_path` fixture; verify security validation rejects `../` paths and system dirs.
- `detect_outliers_resource`: inject known outliers into the sample CSV fixture and assert they appear.
- `find_duplicates_resource`: add duplicate rows to sample CSV fixture and assert they're found.
- #5: assert warm cache hit returns without HEAD request (verify no HEAD in `httpx_mock` calls).
- #6: assert `ckan.py` public functions return `{"error": ..., "hint": ...}` on HTTP failures.
